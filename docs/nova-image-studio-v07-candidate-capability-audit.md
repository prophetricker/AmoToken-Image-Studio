# Nova Image Studio v0.7 候选能力灰度审计

日期：2026-07-07

## 结论

v0.7 默认仍只开放生图工作台、Agent、反推提示词和提示词广场，不向普通用户默认开放 GIF、我的素材、无限画布。

本轮已加入构建时灰度入口：设置 `NEXT_PUBLIC_NOVA_CANDIDATE_MODES=1` 重新构建前端后，标签栏会显示 `动图生成`、`我的素材`、`无限画布`。当前生产部署不设置该变量，因此线上普通用户不可见。

## GIF

现状：
- 入口文件：`frontend/src/components/GifGenerationWorkspace.tsx`
- 工作流：`frontend/src/hooks/useGifWorkflow.ts`
- 模型筛选：`frontend/src/lib/gif-job-store.ts`
- 生成方式：先生成 3264x2448 的 4x3 网格图，再本地切帧编码 GIF。

兼容性判断：
- 当前筛选条件要求 image 系列模型同时支持自定义尺寸且 `maxOutputSize === '4K'`。
- AmoToken 公开主模型目前在前端注册为 `maxOutputSize: '2K'`，所以 GIF 工作区即使打开，也会显示没有可用 GIF 模型。

灰度结论：
- 暂不适合给普通用户测试。
- 可以给管理员做“入口可见但不可用”的验证，主要确认提示文案和无模型状态。
- 真正灰度前需要新增可控的 4K 能力、明确 4K 成本，并确认 3264x2448 网格图稳定。

## 我的素材

现状：
- 入口文件：`frontend/src/components/assets/AssetsWorkspace.tsx`
- 存储：浏览器本地 IndexedDB/localStorage，不依赖服务端账号体系。
- 主工作台已经可以从素材库导入参考图，也可以把提示词保存为素材。

兼容性判断：
- 与 AmoToken token-only 设置兼容。
- 不增加服务端存储成本。
- 当前已有搜索、标签、排序、导入导出、编辑、删除等基础能力。

灰度结论：
- 最适合进入下一轮管理员/小范围灰度。
- 默认不开放给普通用户，避免用户误以为素材跨设备同步或永久云端保存。
- 灰度文案要说明“素材保存在当前浏览器，本阶段不保证跨设备同步”。

## 无限画布

现状：
- 入口文件：`frontend/src/components/canvas/CanvasWorkspace.tsx`
- 生成服务：`frontend/src/components/canvas/canvas-generation-service.ts`
- 能力：节点式画布、连线引用、局部生成、提示词广场导入、保存到素材库。

兼容性判断：
- 生成任务已经走 Nova 任务队列，能够复用 AmoToken token-only 的主链路。
- 画布仅适合宽屏，组件内已要求宽屏模式。
- 参数组合复杂，用户很容易选择过多节点或过多参考图，导致失败率和成本感知变差。

灰度结论：
- 可以管理员灰度，不建议普通用户默认开放。
- 灰度重点不是“能不能生成一张图”，而是节点引用、失败恢复、成本提示是否容易理解。
- 后续需要把画布节点生成的费用、耗时和失败原因也接入 v0.6 任务卡片同等级别的解释。

## 下一轮建议

1. 先灰度“我的素材”，因为它对主链路帮助最大，风险最低。
2. GIF 等 4K 模型能力和价格明确后再灰度。
3. 无限画布只给管理员或核心测试成员，先验证复杂工作流，不面向普通用户。
4. 生产仍保留 Basic Auth；候选能力即使灰度，也不代表公开发布。

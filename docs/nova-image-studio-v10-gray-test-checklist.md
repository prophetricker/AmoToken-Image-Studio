# Nova Image Studio v0.10 候选能力灰测清单

日期：2026-07-09

当前线上灰测包：

- 运行镜像：`amotoken/nova-image-studio:v0.10-c7700da`
- 公开入口：`https://img.amotoken.cc/`
- 保护策略：继续保留 Basic Auth，不公开放量
- 普通用户默认入口：不显示 `动图生成` 和 `无限画布`
- 候选能力入口：访问 `/?novaCandidateModes=1`
- 关闭候选入口：访问 `/?novaCandidateModes=0`

## 灰测目标

本轮只验证候选能力是否适合继续小范围灰测，不作为正式发布验收。

需要确认：

- 普通生图、单图编辑、多图融合继续稳定。
- 4K 只在灰测入口可见，并且用户能理解更高费用、更长耗时和失败风险。
- GIF 能完成最小闭环：输入、网格图、切帧预览、下载、失败提示。
- 无限画布能完成高级入口灰测：导入素材、导入提示词广场、节点参考生成、结果保存。
- 失败文案只使用 `生图失败 / 生图服务 / 爱词元记录` 口径。
- 费用继续使用“预估费用 + 实际以爱词元记录为准”。
- 服务器资源没有明显异常增长。

## 测试前准备

测试者需要：

- Basic Auth 用户名和密码。
- 低额度 AmoToken 专用令牌。
- Chrome 或 Edge 最新稳定版。
- 至少 3 张本地参考图，用于单图编辑、多图融合、无限画布。
- 记录每次任务的大致耗时、是否成功、预估费用、爱词元记录里的实际扣费、失败提示。

建议先用低复杂度提示词，确认通路后再试复杂图。

## 入口验证

1. 打开 `https://img.amotoken.cc/`。
2. 输入 Basic Auth。
3. 不带候选开关进入首页。
4. 确认标签栏不显示 `动图生成` 和 `无限画布`。
5. 访问 `https://img.amotoken.cc/?novaCandidateModes=1`。
6. 确认标签栏显示 `动图生成` 和 `无限画布`。
7. 访问 `https://img.amotoken.cc/?novaCandidateModes=0`。
8. 确认候选标签消失。

通过标准：

- 普通入口不会暴露候选能力。
- 候选入口只影响当前浏览器。
- 关闭候选入口后，页面能回到普通主流程。

## 普通主链路回归

用候选入口打开后，先确认普通主链路没有被影响。

必测：

- 文生图：`1K`、`1:1`、`1` 张。
- 单图编辑：上传 1 张参考图，做轻量修改。
- 多图融合：上传 2 到 4 张参考图，做融合生成。
- 任务卡片：缩略图、提示词首行、模型、尺寸、耗时、预估费用、下载、放大、复制完整提示词。
- 添加到素材库：点击后按钮反馈正常，重复点击能识别已添加状态。

通过标准：

- 三条普通链路均能成功生成。
- 失败任务保留卡片，文案清楚，不暗示一定已扣费。
- 任务卡片操作不影响页面布局。

## 4K 灰测

入口：

1. 打开 `/?novaCandidateModes=1`。
2. 在模型选择中选择 `AmoToken GPT Image 2 4K 灰测`。
3. 在尺寸选择中选择 `4K`。

预期界面：

- 出现 `4K 灰测提醒`。
- 提醒说明预计耗时更长、费用更高。
- 提醒建议先用 `1K` 或 `2K` 定稿，再升到 `4K`。
- 费用提示仍显示为预估，实际以爱词元记录为准。

建议测试：

- 4K 文生图 1 张。
- 4K 单图编辑 1 张参考图。
- 4K 多图融合 2 到 4 张参考图。

记录项：

- 提示词。
- 选择的比例。
- 是否成功。
- 页面耗时。
- 页面预估费用。
- 爱词元记录里的实际扣费。
- 图片质量评价。
- 失败提示原文截图。

当前灰测价格区间：

- 4K 文生图：约 `¥0.15-0.20`
- 4K 单图编辑：约 `¥0.16-0.20`
- 4K 多图融合：约 `¥0.18-0.20`

通过标准：

- 4K 只在候选入口可选。
- 普通模型不会被污染成 4K。
- 失败提示不出现内部服务词。
- 如果失败，用户能理解可以降低尺寸、减少复杂度或稍后重试。

## GIF 灰测

入口：

1. 打开 `/?novaCandidateModes=1`。
2. 进入 `动图生成`。
3. 确认模型显示 `AmoToken GPT Image 2 4K 灰测`。

建议提示词：

- `一只小鲨鱼眨眼并轻轻挥手，动作连贯，背景简单`
- `一个小机器人转身打招呼，动作清楚，干净背景`

必测流程：

1. 输入短动作提示词。
2. 可选上传 1 张参考图。
3. 点击生成网格图。
4. 确认生成的是 `4x3` 网格，共 `12` 帧。
5. 进入审查与导出。
6. 调整帧间隔或边缘裁切。
7. 合成 GIF。
8. 下载 GIF。
9. 重新下载一次已合成 GIF。
10. 失败时检查面板标题是否为 `生图失败`。

费用口径：

- 网格图生成会产生预估费用。
- GIF 合成在浏览器本地完成，不额外扣费。
- 实际以爱词元记录为准。

通过标准：

- 能完成网格图到 GIF 下载的闭环。
- 失败时不会下载空结果。
- 失败提示不出现内部服务词。
- 测试者能区分“网格图生成费用”和“本地 GIF 合成”。

## 无限画布灰测

入口：

1. 打开 `/?novaCandidateModes=1`。
2. 切换宽屏模式。
3. 进入 `无限画布`。

必测流程：

1. 新建画布。
2. 创建文本节点。
3. 创建图片节点。
4. 从素材库导入图片。
5. 从提示词广场导入提示词或示例图。
6. 使用图片节点作为参考图生成新图片。
7. 生成结果保存到素材库。
8. 刷新页面后确认画布项目仍可打开。
9. 故意用缺令牌或无效任务触发失败提示。

预期文案：

- 缺令牌：`请先粘贴 AmoToken 令牌`
- 生成失败：`生图失败`
- 保存成功：`已存入我的素材`

通过标准：

- 高级入口可用，但不影响普通主流程。
- 生成失败不会暴露内部服务词。
- 结果可以保存到素材库。
- 画布节点不明显丢失、不明显卡顿。

## 运行稳定性观察

每轮 5 到 10 人灰测后，管理员运行一次只读快照：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\collect-nova-runtime.ps1 -SshTarget root@43.255.156.149 -IdentityFile "$env:USERPROFILE\.ssh\amotoken_nova_deploy" -OutputPath "output\nova-runtime-$(Get-Date -Format yyyyMMdd-HHmmss).md"
```

重点看：

- Nova 内存是否持续增长。

- 任务数据库 WAL 是否持续增长。

- 日志是否出现连续失败或缓存错误。

- Nova 数据目录约 `20M`

## 继续灰测判断

可以继续扩大到 5 到 10 人灰测的条件：

- 普通主链路成功率稳定。
- 4K、GIF、无限画布的问题不影响普通用户。
- 失败提示能被用户理解。
- 爱词元记录能核对实际扣费。
- 提示词图片缓存、任务库、内存没有明显增长风险。

暂不公开放量的情况：

- 4K 多次失败且用户无法理解原因。
- GIF 网格图成功但合成或下载不稳定。
- 无限画布出现节点丢失、明显卡顿或保存失败。
- 服务器资源出现持续增长。
- 费用口径无法和爱词元记录对上。
